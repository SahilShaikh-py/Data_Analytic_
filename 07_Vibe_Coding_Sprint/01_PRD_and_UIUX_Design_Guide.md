# 📋 Vibe Coding Stage 1: Planning, PRD & UI/UX Design

The foundation of any successful software product is disciplined planning. Before writing a single line of frontend or backend code, we define what we are building, who it is for, and how the user interface will look and feel.

---

## 📌 1. The Product Requirements Document (PRD)

A PRD serves as the single source of truth aligning developers, designers, and business stakeholders.

### PRD Blueprint: "DataSense AI — The Natural Language Analytics Copilot"

```markdown
# Product Requirements Document (PRD): DataSense AI

## 1. Problem Statement
Business managers frequently need quick sales, margin, and inventory metrics from company databases but are blocked waiting 3 to 5 days for data analysts to write SQL queries.

## 2. Product Vision & Value Proposition
An intuitive, browser-based analytics portal where non-technical stakeholders type plain English questions (e.g., "Show me top 5 selling products in Mumbai last month") and receive instant SQL queries, data tables, and interactive visual charts generated by AI.

## 3. User Personas
- **Primary:** Sales Director / Operations Manager (Non-technical, needs answers in < 10 seconds).
- **Secondary:** Junior Data Analyst (Needs AI to verify SQL syntax and accelerate chart creation).

## 4. MVP Feature Scope (MoSCoW Framework)
- **Must Have (P0):**
  - Text input for natural language questions.
  - LLM-powered query engine converting English to executable SQL.
  - Interactive tabular preview of SQL query results.
  - 3 Core KPI overview cards.
- **Should Have (P1):**
  - Automatic chart generation (Bar chart, Line trend).
  - Download result as CSV/Excel.
- **Could Have (P2):**
  - Voice-to-text input.
- **Won't Have (P3 - Out of Scope for MVP):**
  - Multi-tenant enterprise SSO (defer to v2).
```

---

## 📌 2. User Stories & Acceptance Criteria

Write features from the perspective of the end user:

1. **User Story 1: Natural Language Querying**
   - *Story:* As a business manager, I want to type questions in plain English so that I do not have to learn complex SQL syntax.
   - *Acceptance Criteria:*
     - Query response time must be under 2 seconds.
     - System displays both the generated SQL query and the final data table.
     - If the question is ambiguous, the AI asks a clarifying follow-up.

2. **User Story 2: Data Export**
   - *Story:* As an operations lead, I want to export query results to CSV so that I can share them in team meetings.
   - *Acceptance Criteria:*
     - Clicking "Export CSV" downloads a valid UTF-8 formatted CSV file matching table data.

## 🎨 3. UI/UX Design Prompts for Google Stitch / v0 / Claude Artifacts

When generating UI designs using AI tools (such as Google Stitch, v0.dev, or Claude Artifacts), provide explicit design tokens:

### Copy-Paste UI Generation Prompt:
```text
Act as a Principal Product Designer & Senior Frontend Engineer.
Design a modern, sleek web application for "DataSense AI — Natural Language Analytics Portal".

Design Specifications:
1. Theme & Aesthetic:
   - Modern dark mode with subtle glassmorphism (slate background #0F172A, card background #1E293B with 0.7 opacity, border #334155).
   - Accent colors: Electric Cyan (#06B6D4) for primary CTAs and Emerald Green (#10B981) for positive metrics.
   - Typography: Clean sans-serif font (Inter / Outfit).

2. Screen Layout (Single Page Web App):
   - Top Navigation Bar: App Logo, Live Database Status indicator ("Connected to PostgreSQL"), and GitHub Profile link.
   - Hero / Search Section: Prominent central input bar with placeholder "Ask anything about your sales data..." and an animated "Ask AI" button.
   - Suggested Chips: Quick-clickable sample questions ("Top 5 Products", "Monthly Revenue Trend", "Highest Spenders").
   - KPI Highlights Bar: 3 metric cards (Total Revenue, Active Orders, Average Margin).
   - Results Workspace: Split view with Generated SQL Editor (syntax highlighted) on left, and Interactive Data Table / Chart on right.

Please output the complete HTML, CSS, and vanilla JavaScript without external dependencies.
```
